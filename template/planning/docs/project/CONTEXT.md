# CONTEXT.md — planning/docs/project/

Planning guides written for this project. The template seeds only this pair, once; from then on
the pair and everything else in the folder are yours, and `copier update` never changes them. A
guide here with the same filename as one in `planning/docs/reference/` overrides it entirely; a
new filename adds a guide the template does not have. This is where the project's own planning
conventions go — the house rules for its outline, its briefs or its registers that no other
project shares.

## Directory Tree

```text
planning/docs/project/
├── CONTEXT.md          ← this file
├── CLAUDE.md           ← operating rules
└── <question>.md       ← one guide per question, in the reference guides' shape
```

## What's here

- Guides you have written, each named in kebab-case for the question it answers, with a line
  here for each. **Until you write one, this folder holds only its pair.**

## Cross-references

- `planning/docs/reference/` — the template's guides, which yours override by name.
- `planning/docs/CLAUDE.md` — the guide shape and the precedence rule.
