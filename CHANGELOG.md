### Added

- **`learning/` in a project with another template (D57)**, at the maintainer's decision (27/10/2026), agreed with syntek-media's maintainer the same day (its D86). While another template's answers file (`.copier-answers.<template>.yml`) stands at the project root, `teach` puts each new topic in `learning/syntek-author/<topic>/`; alone, it writes straight under `learning/<topic>/`, as before. - **An entry the history keeps out is named, once (D51, D54).** A hook entry, a deny or ask rule, a top-level value or an MCP server not added because a committed version of its file held it was recorded as offered without a word. Each now follows every parent (`git log --full-history`) and reads every version of the file, each merge against each parent and the root commit included, whatever the owner's `log.diffMerges` and `log.showRoot` settings; the record lookup, which read merges with `-m`, reads them the same way, and a committed `settings.json` that opens with a byte-order mark, which the walk skipped, is read. The walk needs Git 2.31 or later, as the update command already does; an older Git stops the lane with one line instead of reading an empty history (`update-test.sh` checks 102 and 103).

## [0.5.0] - 22/10/2026

A new project now keeps its binary files (scans, signed and issued copies, archived email, large images, generated audio) outside the repository, under one data root per machine that the owner names in `SYNTEK_DATA_ROOT`, each file listed with its checksum in a committed manifest, so Git keeps the text (D50). An existing project keeps its files in the repository on the update to this release and opts in when it chooses; nothing is moved for it.

The business-only Google Drive question is replaced by `DATA_PROVIDER`, asked in every variant, which records which service the owner runs to keep a copy of the data root; the template never syncs anything itself, and the Drive workflows stay only for a business project that keeps its files in the repository (D53).

Every project now ships two pinned, keyless MCP servers, Scrapling for web pages and code-review-graph for a local map of the project's code, with a prompt before each tool that drives a browser or writes files and a responsible-use rule every session follows (D54).

### Fixed

Defects found by the pre-release review and its audits:

- **`make lint` no longer flags template text**: HTML comments, metadata headers, seed banners, LaTeX command names, list numbers and reference lists are skipped, and the seeds are one sentence per line, so every fresh render lints clean. `make lint` and `make flags` skip ingest reading copies and Drive copies, which are not the author's text.
- **`texcheck.py`** reads URLs, carets, tildes, repeated long-table heads and caption order as Pandoc writes them, compares footnote, scene-break, epigraph and quotation boundaries, and reports Markdown line numbers correctly.
- **Constructed languages:** every string read is NFC-normalised; roots and affixes are checked only against the inventory and forbidden sequences; glyph SVGs styled through CSS are refused; script samples draw positional forms at their own width; `house.lua` sets shared punctuation outside the native script.
- **Verification and review:** any agreed wording change after a gate is promoted again and re-reviewed; V4.4 covers method rules 5 to 8; a correction made in a `.tex` is mirrored into the section's draft and ledger and re-checked; `make docx` of a `.tex` needs the author's `DOCX_CONVERTER`, as every guide now says.
