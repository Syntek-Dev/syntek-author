## [Unreleased]

A new project now keeps its binary files (scans, signed and issued copies, archived email, large images, generated audio) outside the repository, under one data root per machine that the owner names in `SYNTEK_DATA_ROOT`, each file listed with its checksum in a committed manifest, so Git keeps the text (D50). An existing project keeps its files in the repository on the update to this release and opts in when it chooses; nothing is moved for it.

The business-only Google Drive question is replaced by `DATA_PROVIDER`, asked in every variant, which records which service the owner runs to keep a copy of the data root; the template never syncs anything itself, and the Drive workflows stay only for a business project that keeps its files in the repository (D53).

Every project now ships two pinned, keyless MCP servers, Scrapling for web pages and code-review-graph for a local map of the project's code, with a prompt before each tool that drives a browser or writes files and a responsible-use rule every session follows (D54).

### Added

- **The data root (D50).** `DATA_STORE` (always asked; `external` on a fresh copy, `repo` on the update that first asks it and on a copy beside a sibling template's record from before D50, and a sibling's recorded store wherever it holds one) decides whether binary records and issued copies live in the repository or under `<root>/<DATA_AREA>/<kind folder>/<DATA_SLUG>/<repo-relative path>`. The root comes only from the environment variable `SYNTEK_DATA_ROOT`, never from a Copier answer or a tracked file, and is valid only where the owner has created the marker file `.syntek-data-root` (which also catches an unmounted disk); a root that is set but invalid stops the tool, never falling through. Text work never needs a root; issuing and filing exit `2` and never fall back to the repository.
- **Seven data-root questions in the family-shared block (D48, D50).** `DATA_STORE`, then `DATA_AREA` (the owner's folder name, case kept, Windows-safe, at most 64 characters; default `business`), `DATA_SLUG` (default: the project folder's name in kebab case, cut to 64 characters; no default where nothing is left or a device name is, through Copier's `UNSET`) and `DATA_KIND_DOCS`, `DATA_KIND_PHOTOS`, `DATA_KIND_AUDIO`, `DATA_KIND_VIDEOS` (each Windows-safe, none differing from another only in case), the last six asked only under `external`. `_external_data.peer` reads the sibling template's answers file (`.copier-answers.syntek-media.yml`) for `DATA_*` keys alone: a template's first data-root answers default to the sibling's and must equal them, case included; a later difference is allowed, reported by `_message_after_update` and refused by the resolver's data commands until both agree, so neither template can deadlock the other. A change of case alone from a recorded area or kind is refused. A fresh copy prints a second `MissingFileWarning`, for the sibling's file.
- **The data-root resolver, `.claude/syntek-author-dataroot.py`** (template-owned, ungated and family-shared under each template's own name, like D49; Python 3.11 or later, standard library only, no network). `root` (the root, its marker, the layout per kind and the provider's checklist), `store`, `path`, `add` (copy to a temporary name, hash again, then write the row; never overwrite; `--force` keeps the superseded copy, and refuses an evidence row; under `repo`, a `generated` file, or one whose map role says `"repo": "skip"`, exits `0` and writes nothing), `verify` (by checksum only, each file where its row says it was filed; it also fails on a row committed at `HEAD` that was removed or changed other than its `state`, and on a tracked `external.toml` that no map's folder names), `status` (the loss detector: ignored binaries no row lists, large assets, folders that differ from the answers, unlisted files under the project's folders of the root, those outside every map's folders included and never those in a working-output folder, and roles two maps define differently), `pull`, `plan` (copy, never move or untrack), `check-names` (Windows-safe names, a 260-character warning), `guard` and `--self-test`. Exit `0` done, `1` a check failed, `2` it cannot act; a map or manifest that is newer than the resolver, does not parse or is invalid, is reported and refuses only the commands that touch that map's folders. Its extension table decides the kind of a file no map fixes, an unknown extension being a document. It names no template, no folder of any template and no decision number, and its self-test never reads the inherited `SYNTEK_DATA_ROOT`. `guard` runs on Python 3.8 or later and lets every call through on any error of its own.
- **This template's data-root map, `.claude/syntek-author-dataroot.json`** (template-owned, token-free, not family-shared; its format is): the filing folders `library/src/` (every file a document), `research/src/`, `proposal/src/`, `assets/` (a size warning over 1 MiB, `"warn_over_kib": 1024`) and `world/src/`. The resolver reads every template's map and refuses a folder two maps claim. The format lets a folder entry say `"rows": "none"` (working output, which never takes rows and which `status` and `verify` never list) and a map add roles, each `{"name", "evidence"}` with an optional `"repo": "skip"`; this template's map adds no role and marks no folder.
- **The manifest, `external.toml`** (`format = 1`, family-shared, documented in the resolver), one per filing folder, written on the first `add` and committed by the owner: append-only `[[file]]` rows with the path, kind, the folder each file was filed under (so a later change of answers, or a round trip through `repo`, never loses a file), role, evidence flag, checksum, size, date, state, source, `replaces`, label, former name and notes. The role rules are those agreed with syntek-media (16/10/2026). The shared roles are `issued`, `signed`, `ingested`, `received`, `archive`, `evidence`, `asset` and `generated`, of which `signed`, `evidence`, `ingested` and `received` are evidence; a map may add roles, named in lower-case words joined by hyphens (`brand-export`) and never a shared role's or a kind's name, and where two maps define one differently, evidence wins. Each row records `evidence` when it is filed and keeps it; a row is protected where its flag or any present definition says so, and a row whose role no present map defines is reported and treated as evidence. An evidence row's file and checksum are never replaced. Rows are never deleted: the one change in place is a row's `state`, from `current` to `superseded` or `withdrawn`, and a superseding copy is a new row whose `replaces` names the kept copy. A key the resolver does not know, on a row, a map's folder entry or a role entry, is kept verbatim and ignored.
- **Three nested `.gitignore` files under `external`**: `library/src/` (business), `research/src/` and `proposal/src/` (books with a proposal), token-free, ignoring every binary type in any letter case and the tool's temporary files, never `external.toml` or a `README.md`. An ignore rule never untracks a file.
- **`make root`, `make files-add`, `make files-verify`, `make files-status`, `make files-pull` and `make files-plan`** in every variant (`FILE=`, `ROLE=`, `AS=`, `SOURCE=`, `LABEL=`, `GLOB=`; `FORCE=1`, `HYDRATE=1` and `COPY=1` are switches that take only `1`, `yes` or `true`).
- **`.claude/rules/syntek-author/09-data-root.md`**: the store, the rule that a session never searches, lists or edits under a data root, the provider paragraph, and under `external` the root and layout (this project's answers printed), the filing folders, kinds and manifest, and the commands.
- **The data-root guard, for new projects.** The seed `.claude/settings.json` wires a `PreToolUse` hook that runs the resolver's `guard` whatever the store: it blocks an edit or a write at or under a data root (found from `SYNTEK_DATA_ROOT` or by the marker), and a `Grep` or `Glob` search there where the client offers those tools. On macOS, Linux and WSL Claude Code searches through Bash, which the guard does not read, so there it stops edits and writes, not searches. It is never offered to an existing project: the v0.5.0 report and `README.md` give the entry to add by hand.
- **`DATA_PROVIDER` (D53)**, last in the family-shared block, always asked, no validator: `none` (the default), `google-drive`, `onedrive`, `dropbox`, `other-cloud` or `nas`. The owner sets up and runs the service; the template never installs, configures, schedules or runs a sync client, mount or job and never calls a provider's service. The answer tailors the resolver alone: `root` prints the provider's checklist, `status` hints at conflict-copy names, `verify` never opens an online-only file unless `--hydrate` asks, `check-names` adds OneDrive's names and 400-character limit, and every data command refuses a repository and a root that contain one another. A difference from the sibling's answer is reported, never refused.

### Fixed

- **An owner's broad MCP allow is honoured (D51).** The settings lane added an ask even where the owner's `settings.json` allowed the whole server, so Claude Code then prompted for tools the owner had allowed. It now treats an allow of `mcp__<server>`, `mcp__<server>__*` or a tool glob after `mcp__<server>__` as covering the ask, and reports it 'because you allow it' instead of adding it; a deny still yields only to the same rule.
- **`run-all.sh` could report a failed render as a pass**: `generate-all.sh`'s exit status was lost in a process substitution. The tree list now goes to a file and the status is kept.
- **`coexist-test.sh` check 10 never checked syntek-author's permissions script**: it looked for `.claude/syntek-syntek-author-…`, a name that never exists.
- **`update-test.sh` check 59** now reads an `_src_path:` line in a recorded blob only at the start of a line, so the resolver's own self-test text is no longer taken for a machine path.

## [0.3.0] - 04/10/2026

Every section's ledger entry now records how the section moved from its original to its final text, revision by revision and with who made each change, and `make compare` prints that record as a PDF (D45).

### Added

- **The three-stage comparison, in every variant (D45).** `make compare` writes `build/compare/<unit>.pdf` for each unit with ledger entries. `UNIT=<unit>` (the brief's filename stem, or a path ending in it) narrows it to one unit, and `SECTION=<slug>` to one section of it, written to `build/compare/<unit>--<section>.pdf`. Each PDF opens with a cover holding the key, the unit's disclosure row exactly as `make provenance` prints it, with its note, and a table of its sections (origin, stages recorded, revisions, change ratio, promoted). Each section follows in the order of the brief's `sections:` list, with a heading block (its revision list and two change figures), a portrait **redline** (the final text, every added word marked and every removed word struck where it stood, by whoever made the change) and a landscape page in **three columns** (Original, AI edit, Final, aligned by paragraph, the headings repeated on every page the columns run on to; the AI edit is the state after the last `ai` or `author-note` revision). A section reopened since its promotion is shown to its latest revision and labelled reopened, never with its previous final drawn as a later state. Each actor has an Okabe–Ito colour and a line style of its own, so the page reads in greyscale and to colour-blind readers: the AI blue, dashed underline and cross-out; the author's note green, dotted underline and double strike; the author vermillion, solid underline and single strike; a change in an entry written before the record grey, wavy underline and wavy strike, shown but never assigned. A citation, code or maths takes its actor's line around a box, link text takes its actor's colour (unchanged links print black), a short word always carries its dash or dot, and a long marked word or web address can break, so nothing runs off the page. `FORMAT=tex` stops at the LaTeX (`build/compare/<unit>/<unit>.tex`) and needs Pandoc alone; the PDF runs XeLaTeX twice and reports every character a font could not draw. With no entries the target prints 'No sections to compare yet.' and exits `0`; `SECTION=` without `UNIT=` is refused (exit `2`); a malformed entry is left out, listed on the cover, and fails the run once the rest is written; a unit Pandoc or XeLaTeX cannot set is named, the other units are still written, and the run fails. The output is for the author and for disclosure, and is never issued, committed or synced.
- **`tooling/compare.py`** (standard library, Python 3.11 or later) with `units`, `ast --unit U [--section S] … -o FILE` (the comparison as Pandoc JSON) and `--self-test` (no TeX needed; its Pandoc cases run only where Pandoc exists). It reads the ledger through `provenance.py`, so it never reads an entry or brief git ignores (D42). Each state goes through Pandoc and the house filter, so emphasis, quotation marks, links, citations and footnotes are kept and comments dropped. Each step of the chain is compared word by word, as `provenance.py` compares, and no stage an entry does not hold is guessed. **`tooling/compare.yaml`** holds its Pandoc defaults (article class, A4, 10 pt, 18 mm margins), read after `tooling/defaults.yaml`. **`tooling/latex/compare.tex`** is its header include: `xcolor`, `ulem`, `paracol` and `array`; the `\cmp…` macros, which cannot clash with a house macro and never enter a document, so `texcheck.py` never learns them; the key; and a true landscape page, because `pdflscape`'s rotation never reaches the pages `paracol` ships, after which the next portrait page gets its full height back.
- **The revision record (D45, D12).** An entry written from v0.3.0 carries `format: 2` and two optional sections between `## AI original` and `## Author final`. `## Author original` holds the text the loop started from when the AI did not draft it: the first skill to revise an author-drafted section writes it, and it stays empty in an AI-drafted entry. `## Revisions` is the ordered chain of full-text states, oldest first, each opened by one marker, `<!-- revision N · <kind> · DD/MM/YYYY · <skill> (<strength>) · rows a–b -->`. The kind names who made the change, in D38's words: `ai` (an AI suggestion the author accepted), `author-note` (the AI applying the author's own note or flag answer) or `author` (the author's own edits, found by comparing the draft with the last recorded state before anything changes). Whatever differs between the last revision and the Author final is the author's, and a state equal to the one before it is never written. `standards/style/ledger/CONTEXT.md` defines the format, and `CLAUDE.md` the procedure: before a change, after it, at a redraft, at promotion and for a correction after promotion.
- **`provenance.py` reads the record.** Its entries gain `format`, `author_original`, `revisions`, `original` and `chain()`. `check` reports a malformed or out-of-sequence marker, an unknown kind, a date the calendar lacks, a revision with no text, Author original text in an AI-drafted entry, revisions without an Author original in an author-drafted one, a misplaced or repeated heading, a marker under any other heading and a `format` other than `2`; it warns on a revision identical to the state before it, word for word and paragraph for paragraph, so a paragraph break added or removed is a change, and an Author final that differs only in its paragraphs is the author's step. `Entry.reopened` says when a promoted section has changed since and not been promoted again (a revision records its final as `promoted <date>`, or is dated after the promotion); `chain()` then ends at the last revision, because the Author final is the previous one. `disclosure_row()` and the table's headings and note are importable, so `make compare`'s cover prints the same row, and `make provenance` prints exactly what it printed before. An optional heading counts only where the record puts it, so a document's own `## Revisions` part stays in its text. The change ratio is unchanged (AI original against Author final), and an entry without `format: 2` reads exactly as before.
- **The worked example shows all three stages.** The example opening's entry carries an invented `## Author original`, one recorded `improve-section (light)` revision and two decision rows, one accepted and one rejected with the author's reason. So `make compare UNIT=01-example-chapter` shows original, AI edit and final on a new project, and `learn-voice` has a rejection to practise on (Section 3.2). The-turn's and the business example's entries carry `format: 2` with both optional sections empty. Seed-once examples reach new projects only.
- **Audits.** `tooling-smoke.sh` checks 33–37, in every render. A ledger entry planted with a multi-round chain (an `ai`, an `author` and an `author-note` revision, then the author's final) and a numbered list and a quotation in every state gives `make compare FORMAT=tex` LaTeX carrying each actor's macro (33). An entry git ignores beside it never reaches `build/compare/` or the log, while the tracked entry's words do (34, D42). `SECTION=` without `UNIT=` is refused before any output (35). An empty ledger prints 'No sections to compare yet.' and exits `0` (36). The PDF builds where XeLaTeX exists, and is a named skip elsewhere, CI included (37). Check 18 runs `compare.py --self-test` with the other tooling self-tests; it proves, without TeX, that every paragraph shape the redline opens is defined in `compare.tex`. `_common.sh` catalogues `tooling/compare.py`, `tooling/compare.yaml` and `tooling/latex/compare.tex` as shipped to every variant.
