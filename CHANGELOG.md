## [0.2.0] - 04/10/2026

Adopting v0.1.0 into the business repository the variant was extracted from showed that its business layout did not match how that repository works, that the template's rules read project values from places an adopted repository fills differently, and that two build targets could print or overwrite what they should not. This release answers each.

### Added

- **Business document families, chosen per project (D39).** A new multiple-choice question, `BUSINESS_FAMILIES`, offers `business` (proposals, statements of work, client guides and each client's facts; always included, and its validator refuses a list without it), `legal`, `email`, `accounting`, `social-media` and the opt-in `msp-scp`. Each chosen family ships its folder `library/src/<family>/` (with `templates/`, its client folders and `drafts/`), its standard `library/docs/reference/<family>-standards.md` (with any sub-document split from it), its `<family>-documents` skill and its create workflow, `library/workflows/10-create-a-business-document` to `15-create-an-msp-scp-document`. Each family left out ships none of them. Every family path is one `_exclude` line gated `DOC_TYPE == 'business' and '<family>' in BUSINESS_FAMILIES` (Section 3.5).
- **One project-owned settings file (D40).** `.claude/rules/syntek-author/00-project.md` is a new seed, written once from the answers and loaded at launch with the rules, which it outranks: `## Brief`, `## Paths` (with an 'Approvals' role), `## Memory headings`, `## Workflow aliases` and `## Overrides`. A template path with no role is moved by a redirect bullet under `## Overrides`, `` `<template path>` → `<project path>` ``, which every template file honours (rule 01 Section 9). Its build-side twin is the seed `tooling/project.mk` (D43). Both are in `_skip_if_exists`, anchored.
- **Additive adoption (D41).** `copier copy --trust --skip '*' --skip-tasks` adopts a repository by keeping every existing file and adding the template beside it. `adopt/adopt.sh --additive [--answers FILE]` (and the three `<kind>.sh` wrappers) previews that copy and never writes in the repository. It reports what the copy will add and keep (each kept file marked committed, staged, untracked or ignored, so a file left by an earlier attempt is seen before the copy keeps it as the repository's), each file of the repository's beside a same-named template file in a neighbouring folder with the `## Overrides` redirect that makes template files read it, a mode file that would sit inert beside a kept `SKILL.md`, each kept `CONTEXT.md` to extend by hand (and a kept `workflows/CONTEXT.md` without the routing table), two procedures that would share a workflow number, the build settings to set in `tooling/project.mk`, and a kept `Makefile` that would leave the template's targets uninstalled. On a business library it also names every template path the repository's ignore rules hide (with the rule), every kept file a family untick or option-off would later delete, each template signpost added beside the repository's own files, and a kept workflow that would sync the new `drafts/` folders (D37). Its first line names the source and ref it previewed, and its closing command copies from exactly that. `README.md` gives both adoption modes and when to choose each.
- **Project build settings and issuing (D43).** `tooling/project.mk` sets `BRAND_DIRS` (business: where `make flags` looks for brand files; default `standards/brand`), `LOGO_DIRS`, `DOCX_CONVERTER`, `FLAG_EXTRA_RE`, `ISSUE_STATUSES` and `MAINFONT` / `SANSFONT` / `MONOFONT`; the `Makefile` reads it with `-include`. `tooling/latex/symbol-fallback.tex` ships so a Markdown PDF keeps its symbol glyphs. `house-preamble.tex` adds `\houseclassification{<level>}`, which prints a document's classification in the header and footer of every page (`texcheck.py` reads it as layout), and `tooling/latex/skeleton.tex` gains the internal-note block, a version-history table and its family standard's disclaimer rule.
- **The six family skills (D39, Section 5.3).** `business-documents`, `legal-documents`, `email-documents`, `accounting-documents`, `social-media-documents` and `msp-scp-documents` hold each family's document types, required sections, house conventions and pre-issue checks, generalised from the source repository with every business and client detail removed. `msp-scp-documents` keeps its two required-sections sub-documents; the email and msp-scp standards each split one sub-document (`EMAIL-ANATOMY-AND-NAMING.md`, `MSP-SCP-POLICY-SUITE.md`) carrying the family's gate. The email family files by correspondent (`client-emails/`, `supplier-emails/`) rather than `client-docs/`. Each skill has its `Skill(<name>)` deny line in the root `.claude/settings.json` (dev isolation, Section 7).
- **Migrations (D44).** A root `migrations/` folder, with its pair, holds the scripts `copier update` runs when a release moves author work; `copier.yml`'s `_migrations` runs `migrations/v0.2.0-business-families.sh` on business projects crossing v0.2.0, and `migrations/v0.2.0-project-settings.sh` on every project crossing it. Each ends by printing the command that runs it again (a clone of the release, then the script), because the update's own copy of the template is gone by then.
- **Audits.** `generate-all.sh` adds business renders with every family (`msp-scp` included) and with `[business]` alone. New checks: `shipped-variants.sh` 10–11 (each family's skill, folder, standard and workflow ship exactly as chosen, through `fam-<family>` catalogue gates; no unknown or v0.1.0 family folder); `shipped-seeds.sh` 16–17 (`00-project.md` carries its five headings with no alias or override; `project.mk` sets only the D43 settings); `update-test.sh` 13–23 (a real update from the `v0.1.0` tag moves every business file byte for byte with nothing lost, carries each book's changed audience into `## Brief`, keeps a reader test re-answered during the update over an older hand edit and reports that edit as a conflict, and changes nothing on a second run; check 12 also requires the update message to name `BUSINESS_FAMILIES`); `tooling-smoke.sh` 21–32 (no git-ignored file or language folder read, the `ISSUE` guard and switches, `\fillme` counted, a file name git would quote still built, the classification on every page, `BRAND_DIRS` honoured); `adopt-test.sh` 11–24 (an additive copy changes no existing file, and its report names what each section promises, same-named files with their redirect and committed, untracked and ignored kept files included); and `doc-references.sh` check 4 reads a skill's whole description, folded lines included. `lexicon.py --self-test` also proves a language folder whose files git ignores is never found. CI's job [1/3] runs shellcheck (pinned through shellcheck-py) at warning level over `migrations/`, `adopt/`, `.github/scripts/` and the template's hooks; each audit names `# shellcheck source=SCRIPTDIR/_common.sh`, so no warning is disabled.

### Fixed

- **`make flags` and `make lint` read git-ignored folders (D42)** — where credentials and local-only material live — and printed matching lines verbatim. Every scan now keeps only the paths git does not ignore (outside a work tree, the plain list), passing them NUL-separated so a name git would quote is still read; the conlang targets, in the Makefile and the Python scripts, no longer find a language folder whose files git ignores.
- **`make flags` gave a false all-clear** on a library whose open items are marked another way. It now also counts `FLAG_EXTRA_RE` (business default `\[AWAITING USER INPUT\]` and `\fillme`).
- **`make pdf ISSUE=1` silently overwrote an issued PDF.** It now refuses unless `FORCE=1`, issues only at a status in `ISSUE_STATUSES` (default `final`), and refuses while the file has an open flag, `FORCE=1` or not (D13).
- **`make pdf ISSUE=0` issued the PDF.** `ISSUE`, and the new `FORCE`, take `1`, `yes` or `true`; empty is off, and any other value is refused.
- **`make flags` counted the brand seeds' open slots for ever** in a project that keeps its brand elsewhere (an update restores a deleted seed), so `STRICT=1` always failed. `BRAND_DIRS` in `tooling/project.mk` now names the brand folders it reads.
- **A logo resolved to whichever copy TeX found first** in a recursive search. `LOGO_DIRS` now come first on the search path.
- **`make pdf FILE=` refused a file under a dot-folder** (TeX will not write a job name that starts with a dot). The build name now drops the leading dot.

### Migration

- **Business projects, from v0.1.0:** update on a branch as usual, `uvx copier update --trust -a .copier-answers.syntek-author.yml`. The update asks `BUSINESS_FAMILIES` for the first time (`--defaults` takes every family but `msp-scp`; pass `--data 'BUSINESS_FAMILIES=[…]'` to choose), deletes the old family folders' signposts (even where you edited them; your lines remain in git history), and runs `migrations/v0.2.0-business-families.sh`. That moves every file you created in an old folder to its family, keeping sub-paths — `proposals` → `business`, `contracts` → `legal`, `policies` → `business` (or `msp-scp` when chosen), `correspondence` → `email` (`client-docs/` into `client-emails/`), `finance` → `accounting`, `marketing` → `social-media` — only into a family the update delivered and only where the destination is free. It never overwrites or deletes a file, always exits `0` and is safe to run again. It lists, for you to decide: each file it could not move and why; each line in a tracked file that still cites an old folder; each deleted signpost, with the family file that takes your lines (`git show HEAD:<path>` recovers them); each moved client folder or template the new `CONTEXT.md` does not name; a client's `## Facts` left in `legal/`; a LaTeX letter under `email/`; an email not yet in its `client-emails/<client>/<family>/` folder; and the v0.1.0 family headings in `document-register.md`, `review-schedule.md` and `precedence.md`. Review `git status`, point the listed citations at their new paths, and commit. `README.md` ('Updating a project') gives the detail.
- **Every project, from v0.1.0:** brief values (audience, reader test and the variant's answers) are now read only from `.claude/rules/syntek-author/00-project.md` `## Brief`. `migrations/v0.2.0-project-settings.sh` compares each bullet with where v0.1.0 kept it: `.claude/CLAUDE.md` Section 1, a `Reader test:` entry in `.claude/MEMORY.md`, the trading name in `standards/brand/disclaimers.md` and the style sheet's `## Project settings`. Where a bullet still reads your recorded answer and those files hold exactly one other value, it writes that value and prints the change; every other difference is listed with file and line. An answer you give again during the update itself (`--data`, or a new answer at the prompt) is kept, and an older hand edit is listed as a conflict instead. It edits no file but `00-project.md` and always exits `0`.
- **Every project:** the update writes the two new seeds, `.claude/rules/syntek-author/00-project.md` and `tooling/project.mk`, from your answers. Fill in `## Paths`, `## Memory headings`, `## Workflow aliases` and `## Overrides` wherever the project departs from the template's defaults, and move project rules the template should honour out of numbered sections of `.claude/CLAUDE.md`.
- **Seeds you already have are not rewritten,** and some still give v0.1.0's guidance. The settings migration lists each such line with file, line and the v0.2.0 text to put in its place; change them by hand. In every variant: `.claude/CLAUDE.md` ('the eight files' and 'never edit them' over the whole rules folder, which now holds the editable `00-project.md`, and any numbered section cited), `CONTEXT.md` and `.claude/CONTEXT.md` (the rules folder's 'never edit' tree line, and the brief in `.claude/CLAUDE.md` Section 1), `.claude/skills/CLAUDE.md` and `.claude/skills/CONTEXT.md` (a project rule 'in `.claude/CLAUDE.md` Section 3'), `README.md` ('Never edit `.claude/rules/syntek-author/`', and Sections 1 and 3), `.claude/MEMORY.md` (the reader test, now kept in `## Brief` alone) and `standards/style/style-sheet.md` ('change them here' under `## Project settings`, whose values `00-project.md` now holds). In business also `standards/brand/brand-voice.md` (the trading name is in `00-project.md` `## Brief`, not `disclaimers.md`), and add a `## Policy review-date notice` heading to `standards/brand/disclaimers.md` if you write policies.
- **The migrations run only when the update crosses the `v0.2.0` tag.** An update to an untagged `HEAD` still numbered 0.1.x does not run them, and neither does a later update (choosing a family you left out, say). Each script ends by printing the command that runs it again from the project root, with the source in your answers file filled in: `{ test -d "${TMPDIR:-/tmp}/syntek-author-v0.2.0" || git clone --depth 1 --branch v0.2.0 <source> "${TMPDIR:-/tmp}/syntek-author-v0.2.0"; } && bash "${TMPDIR:-/tmp}/syntek-author-v0.2.0"/migrations/v0.2.0-business-families.sh` (or `v0.2.0-project-settings.sh`). Choose a family, commit, then run it.

## [0.1.0] - 03/10/2026

The first release: one Copier template generating writing repositories in three variants, built to the contract in `DESIGN.md`.

### Added

- **Three variants from one template** (`DOC_TYPE`, always asked, no default): `theology` (a Christian non-fiction book, content layer `manuscript/`), `fiction` (a novel, `manuscript/` plus `world/`) and `business` (business, legal and client documents, `library/`). Shared files are byte-identical across the variants that ship them; variant differences live in gated files and in one mode file beside each shared skill (D6).
- **Options**, each gating its layer, standard, workflows and skills together: `INCLUDE_PROPOSAL` (books), `INCLUDE_REFERENCES` (all; on for theology), `INCLUDE_SENSITIVE_CONTENT` (books), `INCLUDE_WORLDBUILDING` and `INCLUDE_CONLANG` (fiction), `INCLUDE_DRIVE_SYNC` (business), and `SEED_EXAMPLES` (all; adoption answers false).
- **`copier.yml` in the house idiom** (D2): `_subdirectory: template` (D1), the named answers file `.copier-answers.syntek-author.yml` (D3), the `<% %>` / `<: :>` / `<~ ~>` delimiters, every question with help written to the person answering, validators (kebab-case slug, DD/MM/YYYY date, a brief of at least a sentence) and `when:` gates that always carry their `DOC_TYPE` test; `AUDIENCE` offers choices by variant; `CONTENT_LAYER` and `UNIT_NOUN` are computed and never stored.
- **Four ownership classes, one Copier mechanism each** (D14, Section 3): template-owned files merged by `copier update`; seeds written once if missing (`_skip_if_exists`, every pattern anchored); seed-once examples that stay deleted (a copy-only `_exclude` gate); and author-owned folders that ship only their `CONTEXT.md` and `CLAUDE.md`.
- **One `_exclude` line per gated path**, each gate copied verbatim from `DESIGN.md` Section 3.5, and an empty generated block for the mode files, written by `.github/scripts/gen-mode-excludes.sh`.
- **Post-generation tasks**, all non-fatal: `git init` on copy where no repository exists (adoption-safe), `chmod +x` on the session hook, and `make init` on copy to build the references database where the pipeline ships.
- **The authoring loop** (D10): draft, adapt or improve, promote on the author's word, learn the author's voice from the ledger — with provenance recorded for every section (D12) and the two inline flags `AUTHOR TO CONFIRM` and `VERIFY` (D13).
- **Coexistence with later templates** (D17, Section 9): shared root files are seeds, the template's instructions live in `.claude/rules/syntek-author/`, and the answers file is named for the template.
- **Adoption** (Section 8): `adopt/adopt.sh` (with `theology.sh`, `fiction.sh` and `business.sh`) reports by default and, with `--apply`, makes only the moves with exactly one correct destination; it never overwrites, never deletes and is idempotent. `adopt/examples/` holds invented answers files for each variant.
- **The user guide** (`README.md`), the repository map (`CONTEXT.md`) and the development configuration in `.claude/`, with dev isolation: every template skill denied at the root, and the template's `CLAUDE.md` files excluded from development sessions (Section 7).
- **Self-audits** in `.github/scripts/` (Section 7), run by CI on every push.
- **Answers that would destroy work are guarded (D35).** `copier update` refuses a change of `DOC_TYPE` and touches nothing: `copier.yml` reads the previous answers through `_external_data`, at the cost of a harmless MissingFileWarning. Before every update a message names what turning each `INCLUDE_*` option off deletes, filled-in seeds included, and the generated `README.md` lists those files per variant.
- **Business sections are word-checked (D36).** `tooling/texcheck.py` now ships to every variant. `make section-check FILE=….tex SECTION=<slug> DRAFT=….md` proves the words between a section's marker pair are exactly the promoted draft's, and `promote-section` runs it before it writes the ledger. Citation keys work only in Markdown documents in business; promotion stops on a `[@` bound for a `.tex`.
- **An `author-note` decision in the ledger (D38).** `adapt-section` logs each author's note it applies as `author-note`; `make provenance` counts only `accepted` and `rejected` rows as AI suggestions, and `learn-voice` still mines the notes.
- **The worked example can be practised through review.** A seed-once, author-drafted ledger entry for the example chapter's `opening` section (Section 3.2) joins the-turn's, and `provenance.py check` reports the example's missing register rows as a warning rather than a failure.
- **New seeds (Section 3.1).** `standards/brand/brand-voice.md` and `brand-guide.md` (business), `planning/src/maps/CONTEXT.md`, and the `CONTEXT.md` and `CLAUDE.md` of every `docs/project/` and `workflows/local/` are now written once and never overwritten by `copier update`. The house marks of running copy move to `standards/method/BUSINESS.md` rule 10, and the brand files hold only the business's own entries.
- **Tooling self-tests.** `provenance.py`, `lexicon.py` and `script.py` gain a `--self-test` beside `texcheck.py`'s.
- **Audits.** `update-test.sh` proves the `DOC_TYPE` refusal and the option-off message, and that deleted example ledger entries stay deleted; `shipped-seeds.sh` checks index seeds (check 14) and brand seeds (check 15); `adopt-test.sh` checks the unanchored-`build/` advisory; `tooling-smoke.sh` runs every tooling self-test in every render, and in business a `make section-check` pass and a one-word mutation that must fail (checks 18 to 20).

### Changed

Refinements from the pre-release review, made before any project was generated:

- **Drive sync pushes only issued work and never overwrites the record (D37).** Push uploads the PDF beside a `.tex` marked `% status: final`, `.docx` and `.xlsx` files, and Markdown with `status: final` in its frontmatter, never drafts or ingest reading copies (now `<name>.reading.md`). Pull adds new files and writes a differing Drive copy beside the tracked one as `<name>.drive-DD-MM-YYYY.<ext>`, reported, and never pulls a PDF beside a `.tex`. The Drive folder must sit in a shared drive; the push checks that first.
- **The audio ignore rule lives in `world/src/.gitignore`** (`languages/*/audio/`), shipped with every fiction project, so turning the conlang kit off no longer un-ignores generated audio (Section 4.3).
- **A business document is registered at the end of its line edit**, before the issue proof, so V6.2 can pass (`library/workflows/05-review-a-document/` step 12; later steps renumber 13 to 16). A review cycle sends a new version through the same review.
- **The theology worked example argues an invented thesis** ('a welcome is not finished at the door; it is finished when the guest is expected back'), unrelated to any source book (Section 3.2, D15); the theology mode-file examples follow it.
- **Ledger rules.** A redraft keeps its entry, the superseded AI original moving into a dated comment; a re-promotion sets `learned: false`; a unit's name, number included (`03-the-ford`), names its ledger entries, its provenance rows and `UNIT=`.
- **Skill routing.** `run-workflow` owns 'what's next?', resuming from a handoff and any job no skill claims; a skill that carries out a workflow runs a same-named `workflows/local/` procedure instead; `spelling` owns 'proofread'; sharper boundaries between `grilling` and `grill-me`, `argument-audit` and building a map, `prototype` and `adapt-section`, `create-creature` and peoples, `approach-a-reader` and the proposal workflow. `grill-with-docs` dates V1, and drafting stops while a brief is still `idea`.
- **`make print`** builds each script's font on its own and goes on when one fails, then reports every character a font could not draw (a `final` print stops on one). `make flags` also reads `.claude/CLAUDE.md`; `make init` never overwrites the database; a theology project's default translation appears in every reference list (`build/nocite.yaml`).

### Fixed

Defects found by the pre-release review and its audits:

- **`make lint` no longer flags template text**: HTML comments, metadata headers, seed banners, LaTeX command names, list numbers and reference lists are skipped, and the seeds are one sentence per line, so every fresh render lints clean. `make lint` and `make flags` skip ingest reading copies and Drive copies, which are not the author's text.
- **`texcheck.py`** reads URLs, carets, tildes, repeated long-table heads and caption order as Pandoc writes them, compares footnote, scene-break, epigraph and quotation boundaries, and reports Markdown line numbers correctly.
- **Constructed languages:** every string read is NFC-normalised; roots and affixes are checked only against the inventory and forbidden sequences; glyph SVGs styled through CSS are refused; script samples draw positional forms at their own width; `house.lua` sets shared punctuation outside the native script.
- **Verification and review:** any agreed wording change after a gate is promoted again and re-reviewed; V4.4 covers method rules 5 to 8; a correction made in a `.tex` is mirrored into the section's draft and ledger and re-checked; `make docx` of a `.tex` needs the author's `DOCX_CONVERTER`, as every guide now says.
- **Fiction:** a culture registers its own name only when it differs from its people's; `pronounce` checks that `espeak-ng` exists before offering it; a stress mark is allowed where stress is lexical; the example research notes give literal access dates and treat Wikipedia as a lead, not a citation; promotion records `first_used` and `first_appears`.
- **Smaller agreements:** a brief's `version` key; the rules' seed list names every seed; the `make` targets table in `.claude/rules/syntek-author/04-build-pipeline.md` matches `make help`; `tone` reads the house marks from method rule 10; `provenance.py` reads an escaped `\|` as text; open set-ups live under `## Open setups` in `planning/src/causality.md` (`standards/method/FICTION.md`); a decision map resolves a batch of related nodes per session; the book-proposal guide names the master text for endorser approaches; `standards/risk/CONTEXT.md` names fiction risk rules 7 and 8; the chapter review runs the sensitivity pass before `final` where that option is on.
