# CLAUDE.md — migrations/

Read order: `.claude/CLAUDE.md` → this folder's `CONTEXT.md` (imported above) → this file → the header of the script you are about to change.

## Purpose (one line)

Carry what an author wrote across a release that moves the folder it lives in, or the place a setting is read from, so that no update strands or reverts author work (DESIGN.md D44).

## How to work here

- **Routing:** the rule is DESIGN.md D44 and D26; the entry and the house shape are in `copier.yml` under `_migrations`; the proof is `.github/scripts/update-test.sh`.
- **Model:** **Opus** for a new migration or any change to what one moves or writes; the mechanical tier for report wording.
- **Concrete steps:**
  1. Write the migration in the same change as the release that moves the folder or the setting. Name it `vX.Y.Z-<what>.sh`, keyed to the release the change shipped in, never the release somebody noticed.
  2. Header in the syntek-base shape: what moved and why the update strands it, the map, what it never does, how it runs, `Exit codes: 0 = always`.
  3. Guard on markers, never on guesses: act on an old folder only once its template `CONTEXT.md` is gone (Copier retired it), move into a new folder only once its `CONTEXT.md` is there (the update delivered it), and write into a new seed only once the update has delivered it.
  4. Add its `_migrations` entry: `version:`, `command: bash "<% _copier_conf.src_path %>/migrations/<script>.sh"`, and `when:` with `_stage == 'after'` plus any variant test.
  5. Prove it in `update-test.sh`: render at the previous tag, act as the author (plant files in every old folder, with one collision and one that must not move; or change a value in its old home, and re-answer another during the update itself), update to the snapshot tagged with `VERSION`, and assert each file moved byte for byte and none was lost, or that the new home took the value and kept the fresh answer. Then commit, run the script a second time and assert nothing changes.
  6. End the report with the command that runs the script again (the update's copy of the template is deleted when it ends): `rerun_cmd` in each versioned script builds it from `_src_path`.
  7. `bash -n` the script, and shellcheck it at warning level, as CI does: `uvx --from shellcheck-py shellcheck -S warning -x migrations/*.sh adopt/*.sh .github/scripts/*.sh template/.claude/hooks/*.sh`.
- **The two family-shared scripts are the stated exceptions** (D44, D48, D51, D52). `family-update.py` is changed the same way as the outside-link script below: with every family template in one release, then `family-shared.sh --write`; its `update` entry stays last in `_migrations` between the `# BEGIN`/`# END family-shared update (D48)` markers, and its `baseline` task last in `_tasks`. To change what the refresh replaces or adds to `settings.json`, edit `family-refresh.json` (this template's own data) and never the script; a hook entry, permission rule or top-level value is offered only where the new render's `.claude/settings.json` also holds it (a top-level value with the same value), and a hook entry only where it names a script in `.claude/hooks/`, by which it is known, so add it to the seed `template/.claude/settings.json` too, gated with its DESIGN.md Section 3.5 string if it is variant-only (`shipped-seeds.sh` check 22 holds the two together). The data file's format is shared by the family (D51): beside `refresh`, the optional `restore` lists project folders whose every file the new render holds is put back on update where it differs, another template's shared version excepted (D56: `how-to`); a script older than the key ignores it; `settings` holds `hooks`, `permissions` (`deny`, `ask`) and, beside them, top-level values such as `"autoCompactEnabled": false` (true, false, a number or a string). A top-level value is added only where the owner's file has no such key; an owner's other value is kept and reported once; it is offered once, like every entry. A script older than the top-level values ignores them, so a sibling template that has not refreshed `family-update.py` still runs; every family template takes the script and the widened format in the same release (`syntek-media` in the release that adopts D52). Beside `settings`, never inside it, the optional `mcp` key (D51, D54) names the servers (`servers`, each `[A-Za-z0-9_-]+`) and, for each MCP file, the key path that holds them (`files`; a path ending `.toml` is TOML). The values are read from the new render's file at that path, never from the data, so a server is offered only to a file the new render holds and the project already has; add a server to the five MCP sources first (they are family-shared: `.claude/CLAUDE.md` Section 7.9), then to `mcp.servers`. `format` stays 1: a script older than the key ignores it. Never list the data-root guard in `settings.hooks` (D50: new projects only), and a server's ask and deny rules go in `settings.permissions` and the seed as for any rule. It is proved by its `--self-test` and by `update-test.sh` and `coexist-test.sh`.
- **The outside-link script** `agents-outside-link.py` is family-shared: change it only with every family template in one release, run `bash .github/scripts/family-shared.sh --write`, and keep it free of template names, decision numbers and delimiters. Its two `_migrations` entries stay first, unversioned, between the D48 markers. It is proved by `update-test.sh` checks 40–43 (and, on a Python older than the minimum, check 101) and its own `--self-test`, not by a version-crossing flow.
- **Definition of done:** an update across the release moves every author file, or carries every value, that has one correct home, leaves and names every other, and a second run changes nothing.

## Guardrails

- **Always exit 0.** A non-zero exit aborts every later migration and leaves the project half-upgraded. Print what needs a human instead.
- **Never overwrite, never delete a file.** An existing destination is reported and both files stay. Only a folder its own moves left empty may be removed. (The outside-link script removes one file, its own held link, and only where an identical `.agents` link already stands. `family-update.py` replaces a shared file only where its bytes equal a recorded render, puts back the new render's bytes on a file under a folder its data names under `restore` (D56: the read-only `how-to/`), never over another template's shared version, a git-ignored file or a file Git does not hold, and only adds to `settings.json` and to the MCP files the project already has (`.mcp.json` and the client files), each entry and each server once, into the owner's own text, writing a file only when it adds one; a top-level value only where the key is absent, never over the owner's value; never a server the owner removed, never into a git-ignored, linked or conflicted file, and never a permission key of a client file, which stays the permissions script's.)
- **Edit only a seed the same release delivered, and only a line that still holds the recorded answer.** Every seed the author already had is reported line by line, never rewritten: what they wrote around the line is theirs.
- **Act only where exactly one result is correct.** Anything that depends on what the author meant is a report line.
- **Never move a git-ignored file to a path git would not ignore, and never read one** (D42): ignore rules written for the old path protect credentials and local-only material. Read only what `git ls-files -co --exclude-standard` lists, and suggest only commands that do the same (`git grep`, never `grep -r`). A tracked binary's size comes from Git's objects (`git cat-file --batch-check`), never from reading the file; no migration reads the data root or `SYNTEK_DATA_ROOT`.
- **A report-only migration is still a migration.** Where a release changes what the author must decide but nothing has one correct new home (v0.5.0's data root), the script moves nothing, prints the same report on every run, and still ends with the re-run command.
- **Idempotent by construction.** A second run finds nothing to move and nothing to write.
- **No personal data.** Fixtures in the test use invented clients, files and values.

## Output & naming

- **Hand-written:** `vX.Y.Z-<what>.sh`, executable, one per change that needs one. The exceptions are `agents-outside-link.py` and `family-update.py`, named without a release because they run on every update, and `family-refresh.json`, the data `family-update.py` reads.
- **Report format:** a `▸` heading; one `moved  <old> -> <new>` or `changed  <setting>: '<old>' -> '<new>'` line per action; then counts, every file left or value not written with its reason, every line still citing an old path or giving old guidance as `file:line` with its replacement, and the re-run command.
